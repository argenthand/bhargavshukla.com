Layout spec mocks: the router, maybe one more

ProblemThe layout is a shallow host for a deep concept: the easter-egg behaviour has no interface of its own, so the whole layout is the test surface. The tab-bar bug (an attachment that read page.url and reset its tap count on every tap) was invisible until a spec mounted the real reactive page.

SolutionMove the abyss, the controller's load-then-open and the tab lap into the look, behind its existing interface. The layout keeps the markup and attaches the gestures. The look also owns the lazy loading of the Controller, so the layout no longer reaches past the interface.

Evidence pnpm lint passes on main with import('$lib/look/components/Controller.svelte') in the layout.
  • locality: the egg rules live in one module
  • leverage: layout and tests cross one interface
  • layout spec loses 3–4 mocks
  • lap and abyss testable without the router
  • closes a leak past ADR 0002's interface
Consistent with ADR 0002 (easter eggs belong to look). Its lint rule uses no-restricted-imports, which does not look at import() expressions, so the layout's lazy Controller import passes lint while breaking the rule in spirit.

One meter for how long the page has been visible

Worth exploringin-process

  • src/lib/analytics/reads.ts (trackRead, 44–69)

Before
flowchart TB
  RC[ReadCount] --> TR[trackRead]
  RC --> TG[trackReading]
  TR --> V1[visibilitychange + performance.now\npause / resume]
  TG --> V2[visibilitychange + performance.now\nvisibleSince / ms]
  TR --> B1[sendBeacon /api/views at 10 s]
  TG --> B2[track read, on hide or leave]
  classDef leak stroke:#dc2626,stroke-width:2px;
  class V1,V2 leak
After
flowchart TB
  RC[ReadCount] --> M[visible-time meter]
  M --> B1[read beacon at 10 s]
  M --> B2[reading report on hide or leave]
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a,stroke-width:3px;
  class M deep

ProblemTwo timers measure the same quantity, visible seconds on the page, with duplicated pause and resume arithmetic and different send channels. They can drift, and both specs test background-tab and hidden-at-start cases separately.

SolutionShare one measure of visible time. The read beacon fires when it reaches a threshold; the reading report fires when the page hides or the visitor leaves.

Evidence ReadCount.svelte calls [trackRead(path), trackReading(path)] together; both use document.hidden and performance.now(). They also gate the author's opt-out differently (trackRead checks optedOut(); trackReading relies on startAnalytics).
  • locality: visibility rules fixed once
  • leverage: two reports, one meter
  • visibility cases tested once
  • ReadCount spec shrinks

ProblemThe token lifecycle (start once, draw once, keep or expire, wait up to N ms, reset on "send another") is a state machine hidden in the card. A double-start race lived there until PR #175. Today the loader is shallow and the card holds the real behaviour.

SolutionMove the token-keeping state and the wait-for-token logic next to the script loader, so the card only asks to start and for a token. The SvelteKit form enhance flow stays in the card: it is a real framework seam.

Evidence Validation is already deep (checkContact, checkField in contact.ts), so it is not part of this candidate. Turnstile is a real adapter pair already (Cloudflare's script in production, a stand-in in specs).
  • locality: race-prone state in one module
  • ContactCard drops its turnstile mock
  • timer and reset cases testable alone
  • turnstile.ts stops being shallow

ProblemThe preview handle is private to the hooks file, so its spec re-implements sequence (25 lines). Separately, content imports mergeDrafts from publishing, though merging drafts is about content in preview.

SolutionMove the preview handle into the publishing domain, and decide whether mergeDrafts belongs to content.

Evidence Rated Speculative: the handles are 3–10 lines, and the logic they call is already tested. The cost being removed is a one-time stub. No cycle exists today.
  • locality: preview rules with verifyCookie
  • one stub fewer in hooks spec
  • import direction reviewed

Considered and rejected

  • Extract validation from ContactCard. checkContact and checkField are already deep and tested in contact.ts.
  • Share the draft/published fetch ritual. Two call sites with different sorts; extracting moves a few lines without concentrating complexity (deletion test). resume.ts does not merge at all.
  • Flatten site/*.ts. motion, share and site each have one job; deleting any spreads logic to callers.
  • Inline content/asides.ts or palettes.ts. Shared by a page and the server, or by a build script; deleting duplicates.
  • Inline page-load.ts. A real wrapper with a spec that every route would otherwise repeat.
  • Export every hook handle. Covered by candidate 7 at lower cost.
