# Domain folders, each with one interface

`src/lib` has one folder per domain (`site`, `content`, `look`, `analytics`, `contact`, `publishing`), and code outside a folder imports it only through its `index.ts` or `index.server.ts`. ESLint fails on anything deeper, because SvelteKit guards `index.server` but not a domain's own `server/` folder. We chose this over layer folders (`client/`, `server/`) because one concept, such as analytics, ended up split across both trees, and over a convention without the lint rule because it would only last until the next hurried import. The easter eggs live in `look`, not their own folder: the glossary files them under the look, and the two import each other, so separate folders would form a cycle through their interfaces. Analytics once read `look/palettes` directly as a second entry, to avoid a cycle; it now spells out the palette ids it accepts, and a spec keeps that list in step with the look (#161). Decided in #157.
